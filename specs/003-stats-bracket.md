# 003：晋级图、射手榜、助攻榜与积分榜

> 状态：草案
> 关联事项：无

## 目标

用户可以在赛程页面上通过 Tab 切换查看淘汰赛晋级树状图、射手榜、助攻榜和小组赛积分榜，全面掌握赛事数据全景。

## 用户故事

作为一名球迷，我希望查看淘汰赛晋级路线、射手和助攻排名以及各小组积分形势，以便了解赛事整体格局和关注球队与球员的表现。

## 范围

- 赛程页面新增 4 个数据 Tab：晋级图、射手榜、助攻榜、积分榜（与已有赛程 Tab 并列）
- 晋级图 Tab 展示从 1/16 决赛到决赛的淘汰赛树状晋级路线，已确定比赛显示队徽和队名，已赛毕显示比分
- 射手榜 Tab 展示进球排名前十球员，含排名、姓名、国籍、进球数、助攻数和出场次数，支持按进球/助攻/出场次数切换排序
- 助攻榜 Tab 展示助攻排名前十球员，结构和射手榜一致，默认按助攻数降序
- 积分榜 Tab 展示小组赛各组积分排名，含排名、球队名、场次、胜、平、负、进球、失球、净胜球、积分，出线球队视觉区分
- 晋级图中未确定的比赛位置显示占位符（如"1A vs 2B"）
- 所有榜单支持空数据状态展示

## 非目标

- 晋级图的动画交互和拖拽属于后续功能迭代范围
- 球员详情页的跳转已在 001 Spec 中覆盖，本 Spec 榜单中的球员姓名点击沿用已有路由
- 射手榜和助攻榜的完整排名（超出前十的部分）本期不做分页和无限滚动
- 积分榜的淘汰赛阶段逻辑（淘汰赛无积分榜）已在页面过滤中处理，不需要额外后台逻辑

## 业务规则

- **BR-01**：晋级图结构从 round-of-32 阶段开始，按树状层级展开至 final，每层包含该阶段的全部比赛
- **BR-02**：已确定的晋级比赛显示对阵双方队名和队徽，已赛毕的显示比分；未确定的显示占位符
- **BR-03**：射手榜默认按进球数降序排列，进球相同按助攻数降序，助攻相同按出场时间少优先
- **BR-04**：射手榜数据来源于球员赛事统计表，进球数大于 0 的球员才出现在射手榜
- **BR-05**：助攻榜默认按助攻数降序，相同按进球数降序，再相同按出场时间少优先
- **BR-06**：小组赛积分榜按小组分组展示，每组内按积分降序 → 净胜球降序 → 进球数降序 → 公平竞赛积分（红黄牌少优先）排列
- **BR-07**：每组积分前两名的球队以视觉方式区分（出线区），第三名及以后为淘汰区
- **BR-08**：所有榜单在数据加载中展示加载骨架，数据为空时展示空状态说明，加载失败时展示错误提示

## Contract 影响

- 结论：新增
- 理由：晋级图、射手榜、助攻榜、积分榜需要全新的数据查询端点
- OpenAPI operation：
  - `GET /api/stats/bracket` — 淘汰赛晋级树（从 round-of-32 到 final 的全部比赛）
  - `GET /api/stats/top-scorers` — 射手榜（支持 `?sortBy=goals|assists|appearances&order=desc|asc`）
  - `GET /api/stats/top-assists` — 助攻榜（支持同上排序参数）
  - `GET /api/stats/standings` — 小组赛积分榜（按组分组）
- 迁移 / 废弃安排：不适用，全部为新增端点

## 验收标准

- **AC-01**：给定淘汰赛数据完整，当用户切换到晋级图 Tab 时，则展示从 1/16 决赛到决赛的完整树状晋级路线
- **AC-02**：给定一场已赛毕的淘汰赛，当用户查看晋级图时，则该场比赛显示对阵双方队名和最终比分
- **AC-03**：给定射手榜数据完整，当用户切换到射手榜 Tab 时，则默认按进球数降序展示排名前十球员及其姓名、国籍、进球、助攻、出场次数
- **AC-04**：给定射手榜已展示，当用户切换排序方式为按出场次数排序时，则列表按出场次数重新排列
- **AC-05**：给定助攻榜数据完整，当用户切换到助攻榜 Tab 时，则默认按助攻数降序展示排名前十球员及其数据
- **AC-06**：给定积分榜数据完整，当用户切换到积分榜 Tab 时，则按小组分组展示各组排名，出线球队与淘汰球队视觉区分
- **AC-07**：给定射手榜或助攻榜无数据（进球/助攻全为 0），当用户切换到对应 Tab 时，则展示空数据说明
- **AC-08**：给定数据接口加载中，当用户切换到任意数据 Tab 时，则展示加载骨架
- **AC-09**：给定数据接口请求失败，当页面完成请求后，则展示错误提示信息
- **AC-10**：给定用户使用键盘操作 Tab 切换，当遍历晋级图 Tab 栏时，则每个 Tab 具备可见焦点状态
